## When to use this

When the same infrastructure pattern — a secure S3 bucket, an EKS node group, an RDS instance — needs to be provisioned across multiple environments or projects. A module encapsulates the resource definitions and their relationships once; callers provide only the variables that differ per environment.

## Module file layout

```
modules/
└── s3-secure/
    ├── main.tf          # resource definitions
    ├── variables.tf     # input variables with types and validation
    ├── outputs.tf       # exported values
    ├── versions.tf      # required_providers and terraform version constraints
    └── README.md        # usage example (generated by terraform-docs)
```

## Snippet

### versions.tf

```hcl
# versions.tf — pin providers to avoid silent breaking changes
terraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = ">= 5.0.0, < 6.0.0"
    }
  }
}
```

### variables.tf

```hcl
# variables.tf

variable "bucket_name" {
  type        = string
  description = "Globally unique S3 bucket name."

  validation {
    condition     = can(regex("^[a-z0-9][a-z0-9\\-]{1,61}[a-z0-9]$", var.bucket_name))
    error_message = "Bucket name must be 3–63 characters, lowercase alphanumeric and hyphens only, and cannot start or end with a hyphen."
  }
}

variable "environment" {
  type        = string
  description = "Deployment environment."

  validation {
    condition     = contains(["production", "staging", "development"], var.environment)
    error_message = "environment must be one of: production, staging, development."
  }
}

variable "retention_days" {
  type        = number
  description = "Number of days to retain non-current object versions."
  default     = 30

  validation {
    condition     = var.retention_days >= 1 && var.retention_days <= 365
    error_message = "retention_days must be between 1 and 365."
  }
}

variable "tags" {
  type        = map(string)
  description = "Additional tags to merge with module defaults."
  default     = {}
}
```

### main.tf

```hcl
# main.tf

locals {
  # Merge caller-supplied tags with module-managed defaults
  # Caller tags take precedence — allows overriding CostCenter, Team, etc.
  tags = merge(
    {
      Environment = var.environment
      ManagedBy   = "terraform"
    },
    var.tags
  )
}

resource "aws_s3_bucket" "this" {
  bucket = var.bucket_name
  tags   = local.tags
}

resource "aws_s3_bucket_versioning" "this" {
  bucket = aws_s3_bucket.this.id
  versioning_configuration { status = "Enabled" }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "this" {
  bucket = aws_s3_bucket.this.id
  rule {
    apply_server_side_encryption_by_default { sse_algorithm = "AES256" }
    bucket_key_enabled = true
  }
}

resource "aws_s3_bucket_public_access_block" "this" {
  bucket                  = aws_s3_bucket.this.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_lifecycle_configuration" "this" {
  bucket     = aws_s3_bucket.this.id
  depends_on = [aws_s3_bucket_versioning.this]

  rule {
    id     = "expire-noncurrent"
    status = "Enabled"
    noncurrent_version_expiration {
      noncurrent_days = var.retention_days
    }
  }
}
```

### outputs.tf

```hcl
# outputs.tf

output "bucket_id" {
  value       = aws_s3_bucket.this.id
  description = "The S3 bucket name. Use as a reference in other resources."
}

output "bucket_arn" {
  value       = aws_s3_bucket.this.arn
  description = "The S3 bucket ARN. Use in IAM policy resource blocks."
}

output "bucket_regional_domain_name" {
  value       = aws_s3_bucket.this.bucket_regional_domain_name
  description = "The regional domain name for the bucket. Use as a CloudFront origin."
}
```

### Calling the module from a root configuration

```hcl
# environments/production/main.tf

module "app_data" {
  source = "../../modules/s3-secure"

  bucket_name    = "my-app-production-data-20261112"
  environment    = "production"
  retention_days = 90

  tags = {
    CostCenter = "platform"
    Owner      = "platform-team"
  }
}

module "app_logs" {
  source = "../../modules/s3-secure"

  bucket_name    = "my-app-production-logs-20261112"
  environment    = "production"
  retention_days = 30
}

# Reference module outputs in other resources
resource "aws_iam_role_policy" "app_s3" {
  name = "app-s3-access"
  role = aws_iam_role.app.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject", "s3:PutObject"]
      Resource = "${module.app_data.bucket_arn}/*"
    }]
  })
}
```

### Publishing a module to the Terraform Registry

```
# Module naming convention required by the registry:
# terraform-<PROVIDER>-<NAME>
# e.g. terraform-aws-s3-secure

# Repository structure for a published module
terraform-aws-s3-secure/
├── main.tf
├── variables.tf
├── outputs.tf
├── versions.tf
├── README.md
└── examples/
    └── basic/
        ├── main.tf
        └── outputs.tf
```

**Key decisions:**

| Decision | Why it matters |
|---|---|
| `versions.tf` as a separate file | Keeps provider constraints isolated. When upgrading a provider, the diff is in one file — not buried in `main.tf`. Callers can override the provider version in their root module. |
| `>= 5.0.0, < 6.0.0` version constraint | A lower bound prevents use with a known-broken provider version. An upper bound prevents the module from silently picking up a major version with breaking changes. Never use `~> 5.0` for a shared module — it allows `5.x` upgrades but blocks `6.x` only implicitly. |
| `validation` blocks on variables | Catch invalid inputs at plan time with a human-readable error message. Without validation, a bad bucket name reaches the AWS API and returns an opaque provider error that is harder to diagnose. |
| `merge()` with module tags taking lower precedence | Callers can override any tag. A module that hard-codes its own tags and ignores `var.tags` forces every caller to fork the module to change a tag. |
| No `provider` block in the module | Modules inherit the provider from the calling root module. Declaring a provider inside a module locks it to specific credentials or region, preventing multi-region or multi-account usage. |
| `sensitive = true` on secret outputs | Marks the output value as sensitive so Terraform redacts it from plan and apply output. Required for any output containing passwords, keys, or tokens that a calling module might propagate. |

## Verify it worked

```bash
# From the root configuration
terraform init
terraform validate
terraform plan

# Generate documentation from variable and output blocks
terraform-docs markdown table . > README.md
```
